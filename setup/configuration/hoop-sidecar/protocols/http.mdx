title: "HTTP"
description: "What the HTTP codec inspects beyond ext_authz, and how an http lane masks responses"
---

An `http` lane inspects requests **and responses**. Envoy's `ext_authz` already hands OPA the method, path and headers of a request, and the lane keeps that arrangement. It adds two things ext_authz cannot do by construction: it reads the response, which is where data leaves the building, and it keys policy on a stable resource identity instead of raw paths.

```yaml config.yaml
listeners:
  - name: httpbin
    protocol: http
    listen: 127.0.0.1:18080
    upstream: httpbin:8080
    identity_header: x-hoop-user      # trust only behind an authenticating proxy
    guardrails:
      rules:
        - name: no-admin-api
          type: http_resource
          resources: ["/admin/**"]
          message: the admin API is not reachable through this proxy
        - name: no-upstream-5xx
          type: http_status           # response-side, so ext_authz cannot ask it
          statuses: ["5xx"]
          message: upstream failure suppressed by policy
```

## The normalized resource

Policy keyed on raw paths needs a regex per endpoint. The codec collapses dynamic segments to `*`, so `/users/12345/orders/98765` becomes `/users/*/orders/*` and one `http_resource` rule covers the endpoint:

| Segment | Collapses |
|---|---|
| All digits (`/users/12345`) | yes |
| A UUID | yes |
| A hex string of 12+ characters | yes |
| A long opaque token (JWT/base64url shapes, 24+ chars) | yes |
| A short slug (`/users/alice`) | **no** |

The slug survives on purpose: nothing distinguishes `/users/alice` from `/users/settings`, and collapsing it would widen every rule written against either without warning. In doubt the codec keeps the segment, so a policy can end up too narrow but never too broad. File extensions survive too (`/reports/12345.pdf` → `/reports/*.pdf`), because a policy may allow `*.csv` and deny `*.sql`.

### Dot and empty segments

The codec resolves the path before it matches a rule: `\` becomes `/`, and `.`, `..` and empty segments resolve. `/x/../admin/users` and `//admin//users` both become `/admin/users`, so `/admin/**` matches them. A trailing slash stays. The audit trail keeps the path as sent.

The sidecar cannot see how an upstream routes: Express 4 runs `/admin/../x` under `/admin`, and GKE Connect Gateway may route the raw membership and leave the rest to a cluster that resolves it. So when the path holds `.` or `..`, `http_resource` rules and the `resources` scope of `http_header` rules also match the path before resolution, raw and resolved on its own. OPA reads that form from `input.metadata["http.resource_unresolved"]`.

## The `http` block

The defaults expose nothing: no bodies, no headers. Everything you capture reaches the policy engine, the audit trail and, where an analyzer is configured, a third party, so capture is opt-in per field.

```yaml
listeners:
  - name: httpbin
    protocol: http
    listen: 127.0.0.1:18080
    upstream: httpbin:8080
    http:
      capture_body: true
      max_body_bytes: 65536       # the default
      headers: [Content-Type]     # allowlist; there is no capture-all
```

| Field | Meaning |
|---|---|
| `capture_body` | Includes request and response bodies in the statement. A `pii` or `pattern_match` rule that reads payloads needs it. It is optional for the analyzer, which judges a request from its request line and headers without it. A lane that holds for review captures request bodies without it; response bodies still need it. |
| `max_body_bytes` | Truncates a captured body. Default 64 KiB. |
| `headers` | Headers exposed to policy, the audit trail and the analyzer, matched case-insensitively. An `http_header` rule may name only headers listed here. `authorization`, `cookie`, `proxy-authorization` and `set-cookie` can never be listed. |
| `sql` | Reads the SQL a JSON API carries in its request body. See [SQL in request bodies](#sql-in-request-bodies). |

## SQL in request bodies

A JSON API that runs SQL carries it in the request body, so an `operation` or `table` rule on the request line matches nothing: `POST /api/2.0/sql/statements` is a `post`. An `http.sql` block reads the SQL out of the body. Each SQL string becomes a statement of its own, right after the request that carried it, and guardrail rules, masking and the audit trail see it as SQL.

```yaml
http:
  sql:
    dialect: spark                                       # how to read the SQL
    fields:
      /api/2.0/sql/statements: statement                 # route: JSON path of the SQL
      /ai-gateway/mcp-services/**: params.arguments.query
    tools: [execute_sql]                                 # MCP tools/call that carry SQL
    refuse: [disposition=EXTERNAL_LINKS]                 # field=value refused before forwarding
    refuse_message: ask for disposition INLINE
```

| Field | Meaning |
|---|---|
| `dialect` | Required. `spark`, `postgres`, `mysql`, `mssql`, `googlesql`, `clickhouse` or `oracle`. |
| `fields` | A route pattern, written as an `http_resource` rule writes it, mapped to the dotted JSON path of the SQL. The longest matching pattern wins. |
| `tools` | A body with a `jsonrpc` member carries SQL only as a `tools/call` naming one of these. A JSON-RPC batch yields one statement per call. |
| `refuse` | `field=value` pairs, compared case-insensitively, that send a request's results around the Sidecar. Such a request is refused with `refuse_message`, whatever the rules say. |

A body that should carry SQL and does not yield it (cut at `max_body_bytes`, not JSON, no string at the path) becomes an `unknown` statement, which a rule naming `unknown` refuses. With `refuse` set, a body cut at the limit or not JSON is refused outright, because its value cannot be checked either. The block captures request bodies, so they reach the audit trail. A lane with `http.sql` cannot set an analyzer that holds for approval yet.

[Databricks](/integrations/databricks) walks through a full lane.

## Identity

`identity_header` names the header your authenticating proxy sets. The lane reads it on **every request**, because Envoy pools upstream connections and sends requests from different callers down one keep-alive connection. The first request names the first session before it opens, so the `session_start` audit row already carries the subject. A later request that names a different principal ends that session (`session_end`) and opens a new one on the same connection (`session_start`), so each request's statement row and `input.context.principal` for OPA carry its own caller. A caller change while an earlier response on the connection is still outstanding is refused with a 403 under rule `identity`: that response belongs to the session that sent its request. A request without the header, or with a blank one, names nobody and runs as the connection identity: `anonymous`, or the mTLS subject on a lane that verified one. It is forwarded, not refused, and it ends the session of a caller a previous request on the connection named, so nothing runs under a borrowed name. A policy that requires a caller must deny `input.context.principal == "anonymous"` itself. The header value reaches policy input and the audit trail only when `http.headers` names it. A client that connects and sends no request within ten seconds is closed with no session and no `session_start`, the way a pgwire client that abandons its handshake is; HTTP has no server greeting, so waiting on the client's first bytes is the protocol's own ordering.

Trusting a header is safe only when nothing but that proxy can reach the listener, so bind loopback or a unix socket. On a listener reachable from anywhere else, a caller can assert any identity.

### Google identity

`google_identity` names the caller from Google's own bearer, for a lane with no authenticating proxy in front. kubectl through [GKE Connect Gateway](/setup/configuration/hoop-sidecar/protocols/kubernetes#gke-connect-gateway) sends a Google OAuth2 access token on every request; without this block, Envoy would need `ext_authz` only to learn the name the token already holds.

```yaml
listeners:
  - name: gke
    protocol: http
    google_identity: {}         # the caller is whoever holds the request's Google bearer
    # google_identity:
    #   tokeninfo_url: https://...   # Private Service Connect or a private.googleapis.com VIP; https only
```

- The lane verifies the request's `Authorization: Bearer` token with a POST to `https://oauth2.googleapis.com/tokeninfo`. It never sends the token in a query string, because proxies log URLs.
- The principal is the verified email, else the account's Google `sub`.
- A verified answer is cached under the token's SHA-256 for the token's lifetime, at most five minutes. A rejected token is cached for 30 seconds. An unreachable Google is never cached.
- Any failure (no bearer, a token Google rejects, Google unreachable) refuses that request with a 403. A caller that cannot be verified is never served under the identity the connection had before.
- The token reaches no audit row, no policy input and no analyzer prompt.
- `http` lanes only, and exclusive with `identity_header`: startup refuses a lane that sets both.

The result names who holds the token, not what it may do. The upstream still checks the same token against its own IAM and RBAC. The tokeninfo call trusts the [`trust.ca_file`](/setup/configuration/hoop-sidecar/config-file#adding-a-ca-to-the-trust-store) bundle, so it works through a proxy that re-signs egress TLS.

### Caller token

`caller_token` admits a caller by a shared token, for a listener on a public URL with nothing in front to authenticate the caller. An agent on [Claude Managed Agents](/integrations/claude-managed-agents) or the [OpenAI Agents API](/integrations/openai-agents) calls a listener this way. An [Amazon Bedrock AgentCore](/integrations/aws-agentcore) agent sends the same token to a plain HTTP listener inside a VPC, where the token names the caller in the audit trail.

```yaml
listeners:
  - name: payments-api
    protocol: http
    listen: 0.0.0.0:8443
    upstream: https://payments.internal
    downstream_tls: {cert_file: /etc/tls/tls.crt, key_file: /etc/tls/tls.key}
    caller_token:
      header: X-Hoop-Token                       # the default
      file: /etc/hoop-inspect/caller-tokens      # one token per line; required
      name: claude-managed-agents                # the principal in the audit trail; required
```

- **What is refused.** No header, an empty or whitespace-only value, a value not in the file, or the header sent twice. Each gets a 403 and reaches no upstream. The refusal is audited under principal `anonymous` with rule `identity`.
- **Checked first.** Policy judges a request after its body arrives, and the lane holds the request until then. The token is checked on the request headers, before the body. A caller without the token costs no held body, and a request whose body never arrives is refused too. This holds over HTTP/1.1 and HTTP/2.
- **What is admitted.** Every row of an admitted request names `name` as the principal. A token names no person, so per-user rows need a per-user token.
- **The token stays in the Sidecar.** The Sidecar removes the header before the upstream. The token never reaches an audit row, policy input or an analyzer prompt.
- **Refused at startup.** `--validate` and startup refuse an `http.headers` entry that names the token header. They also refuse a `header` that the upstream, HTTP framing or the Sidecar already uses, such as `authorization`, `cookie`, `host` or `via`.
- **Only the header is removed.** An admitted caller that copies the token into another header, a chunked trailer or the body sends it on.
- **The reserved route is guarded too.** [`/.well-known/hoop/`](/setup/configuration/hoop-sidecar/agent-approvals#read-the-status-on-an-http-listener) answers only a caller the token admits.
- **Closed connections.** The lane closes the connection when it cannot read a request head, when the client sends bytes before the server answers an `Upgrade` or `CONNECT`, or when the codec cannot decode client bytes. After the server grants a switch, the tunnel is not checked again.
- **No TLS of its own.** The token travels as written. Set `downstream_tls`, or put TLS in front of the listener.
- `http` lanes only, and exclusive with `identity_header` and `google_identity`.

**The file.** It holds one token per line. Blank lines and surrounding whitespace are ignored. A token holds no whitespace, comma or control character, because a repeated header arrives joined as `a, b`. The Sidecar keeps only SHA-256 digests in memory and compares every candidate with every token in constant time.

**Rotation.** The Sidecar checks the file every ten seconds and re-reads it when its size or modification time changes. `SIGHUP` re-reads it at once. A file that is missing, empty or malformed on a re-read keeps the tokens in force and logs one warning. To rotate without a refused request:

1. Add the new token as a second line.
2. Update every caller to the new token.
3. Remove the old line.

**Revocation.** Write the file without the token. An empty file keeps the old tokens in force, so to revoke the only token, write a new token in its place or stop the listener. A missing or unusable file at startup, or under `--validate`, stops the process with an error that names the file. The Control Plane never reads the file. A change to the `caller_token` block needs a restart.

**From a Managed Agents vault.** A vault credential can fill the token at egress, so the sandbox holds only a placeholder. See [Claude Managed Agents](/integrations/claude-managed-agents#setup). A request that reaches the Sidecar with the placeholder is refused like any wrong token. A vault rotation reaches running sessions on its own schedule, so rotate with the two-line overlap above.

**From an OpenAI vault.** The vault fills the placeholder anywhere in a request to the Sidecar's host, the URL and the body included, and has no setting that limits where. Keep the token in its header. See [Tokens go in headers only](/integrations/openai-agents#tokens-go-in-headers-only).

## h2 and h2c

An http lane accepts HTTP/2 beside HTTP/1.1:

| Lane | Client can send |
|---|---|
| No `downstream_tls` | HTTP/1.1, or h2c by prior knowledge: a connection that opens with the HTTP/2 preface is HTTP/2, so Envoy can forward h2 without downgrading it. `Upgrade: h2c` is not honoured. |
| `downstream_tls` | `h2` or `http/1.1`, chosen by ALPN. kubectl picks h2 from anything that offers it. |

Each h2 stream is bridged into the unchanged HTTP/1.1 relay as one request, so policy, the per-stream 403, masking, audit, per-request identity and `Via` apply to it exactly as to an HTTP/1.1 client. The upstream hop stays HTTP/1.1. Streams do not count toward `max_conns`: the client connection was admitted once, and HTTP/2's concurrent-stream limit bounds its streams.

An h2 `CONNECT`, extended CONNECT included, gets `501`. A request with an `Upgrade` header (kubectl `exec`, `attach`, `port-forward`) must reach the lane as HTTP/1.1. kubectl already does that when it talks to the lane directly; an Envoy with an h2 cluster to the lane needs a route that sends `Upgrade` requests to a second, HTTP/1.1 cluster. See [The Envoy lane](#the-envoy-lane).

## Via and loop detection

Every http lane appends `Via: <request version> hoop-<16 hex>` as the last request header, so the upstream sees one extra header. The pseudonym is random per process. A request that already carries this process's pseudonym is refused with a 403 whose message starts `request loop:`. That catches a transparent MITM proxy that routes the Sidecar's own upstream traffic back into its listener, where each lap would otherwise look like a fresh client. After a request with `Upgrade`, or a `CONNECT`, the rest of that connection is another protocol and is no longer marked.

## Masking

The codec rebuilds the response around the masked values. A JSON body is walked value by value, and each string or number reaches the masker under its dotted key path (`data.password`, `items.metadata.name`), so a `columns` rule names a JSON key the way it names a result-set column and masks it whatever it holds. A text body (`text/*`, XML, YAML, form data, or no `Content-Type`) is masked as text. Binary types pass through untouched.

`Content-Length` is corrected. A chunked body is re-chunked and streams: each complete top-level JSON value, or each line of text, goes out as soon as it is whole, so a watch or a log follow is not held to its end and a value split across two chunks is still masked whole. A gzip or deflate body is undone around the masker and compressed again. A text or JSON body under an encoding the codec cannot undo (zstd, br, lz4) is refused with a 403 and an `error` audit row rather than forwarded unmasked; a binary body under such an encoding passes. A JSON or text body too large to mask is refused the same way: one held past 8 MiB as sent, or a gzip or deflate body that inflates past 16 MiB. The lane keeps serving after the refusal. Older Sidecars could forward such a body unmasked.

See [Kubernetes API](/setup/configuration/hoop-sidecar/protocols/kubernetes) for `columns: [data]` against kube-apiserver's chunked responses, and the [ClickHouse](/setup/configuration/hoop-sidecar/protocols/clickhouse) HTTP interface for TSV, `JSONEachRow` and `FORMAT JSON` results.

## A request leaves whole

From 1.258.0, the lane forwards an HTTP/1.1 or h2 request only once its body has arrived and policy has judged it. A denied request reaches no upstream, however the client split its bytes.

An older Sidecar forwards the request line and the headers before the verdict. A route that acts on the headers alone then runs even when policy denies the request.

What it costs:

- A request larger than 8 MiB, headers and body together, is refused. Nothing of it reaches the upstream.
- A chunked body the lane cannot frame is refused at once with a 403. The lane would otherwise wait for it forever.
- A streaming upload reaches the upstream only once it ends.
- A client that sends `Expect: 100-continue` sends the body only after its own timeout, 1 second by default in curl and in Go's `http.DefaultTransport`. The upstream has not seen the headers, so no `100 Continue` comes back. curl sends the header for a body over 1 MiB, and `-H 'Expect:'` removes it. Go sends it only when the caller sets it.
- A WebSocket message sent in fragments does not wait for its last fragment. Its earlier fragments reach the upstream before the message is judged.

## Denials

A denied request returns `403 Forbidden` with the rule's message and `Connection: close`:

```
HTTP/1.1 403 Forbidden
Content-Type: text/plain
Connection: close

the admin API is not reachable through this proxy
```

A request refused for its [identity](#identity) or as a [request loop](#via-and-loop-detection) is also answered with a 403. On an h2 connection the 403 ends that stream only.

## The Envoy lane

Keep your existing `ext_authz` filter, and OPA still answers reachability first. The one change is the route's cluster, which points at the Sidecar instead of at the service:

```yaml envoy.yaml
route_config:
  virtual_hosts:
    - name: inspect
      domains: ["*"]
      routes:
        - match: { prefix: "/" }
          route:
            cluster: hoop_inspect_http     # was: the service cluster
            timeout: 60s
```

Envoy already terminated the client's TLS on the HTTPS listener, so this lane carries plaintext HTTP/1.1 or h2c to the Sidecar and there is nothing extra to configure. The compose stack's `httpbin` lane in [`deploy/docker-compose/envoy-stack/`](https://github.com/hoophq/hoop/tree/main/deploy/docker-compose/envoy-stack) runs exactly this shape:

```bash
curl -sk https://envoy:8443/anything -H 'x-hoop-user: alice'
```

To keep h2 on the hop to the lane, give Envoy two clusters to the same lane port: one with `http2_protocol_options` for ordinary requests, one plain HTTP/1.1 for upgrades. Match `Upgrade` first, because Envoy turns an upgrade on an h2 cluster into an extended CONNECT, which the lane answers with `501`:

```yaml envoy.yaml
routes:
  - match:
      prefix: "/"
      headers: [{ name: upgrade, present_match: true }]
    route: { cluster: hoop_inspect_h1, timeout: 0s }    # kubectl exec, attach, port-forward
  - match: { prefix: "/" }
    route: { cluster: hoop_inspect_h2c, timeout: 0s }   # everything else, no downgrade
```
