The Sidecar runs in your infrastructure, between your MongoDB clients and your Atlas cluster.

Clients point their connection string at the Sidecar. Every command from an AI agent, a backend, `mongosh` or Compass then passes through your guardrails, masking rules and audit trail.

<Warning>
The Sidecar sees driver connections only. The Atlas UI, including Data Explorer, reaches the cluster inside Atlas, so its traffic does not pass through the Sidecar. Atlas project roles decide who can browse data there.
</Warning>

---

## Requirements

- An Atlas cluster. The free M0 tier works.
- A database user with a password.
- Docker on a host with a static public IP.
- A MongoDB client, such as `mongosh`.

## Setup

<Steps>
  <Step title="Find the primary member">
    An Atlas connection string starts with `mongodb+srv://`. Its host is a DNS record that lists the cluster members, not a server. The Sidecar connects to one member: the primary.

    Ask the cluster which member is primary:

    ```bash
    mongosh "mongodb+srv://<user>:<password>@cluster0.<id>.mongodb.net/" --quiet --eval 'db.hello().primary'
    ```

    ```
    ac-<prefix>-shard-00-01.<id>.mongodb.net:27017
    ```

    The Atlas UI shows the same. Open the cluster, then the **Metrics** tab. Each member carries `P` for primary or `S` for secondary.

    <Frame>
      <img src="/images/integrations/mongodb-atlas-cluster-members.png" alt="Atlas Metrics tab for Cluster0 with three members, the middle one marked P for primary" />
    </Frame>

    | Host | Use with the Sidecar |
    |---|---|
    | The primary member, port `27017` | **Yes.** |
    | A secondary member | No. Writes fail with `NotWritablePrimary`. |
    | The `mongodb+srv://` host | No. It is a DNS record, not a server. |
    | A private endpoint host | Not covered on this page yet. |
  </Step>

  <Step title="Write the config">
    Save this as `config.yaml`. Replace the `upstream` host with your primary.

    ```yaml config.yaml
    admin:
      listen: 0.0.0.0:19000

    audit:
      file: "-"
      query_sessions: 500

    guardrails:
      rules:
        - name: no-destructive-commands
          type: operation
          operations: [drop, delete]
          message: destructive commands are blocked by Hoop

    mask:
      rules:
        - {name: emails, columns: [email], strategy: redact}

    listeners:
      - name: atlas
        protocol: mongodb
        listen: 0.0.0.0:27017
        upstream: ac-<prefix>-shard-00-01.<id>.mongodb.net:27017
        upstream_tls: {}
    ```

    - `guardrails` blocks `drop` and `delete` commands.
    - `mask` replaces the value of every `email` field in results, nested fields included.
    - `audit` writes every command to stdout as JSON lines, and `query_sessions` turns on the `/api/sessions` endpoint.
    - `upstream_tls` encrypts the hop to Atlas. Atlas certificates come from a public CA, so the Sidecar verifies them with no extra file.
    - `admin` serves health checks and the audit API. It has no authentication, so the next step publishes it on loopback only.

    The config holds no database password. The Sidecar relays the login from the client to Atlas.
  </Step>

  <Step title="Validate and start the Sidecar">
    ```bash
    docker run --rm \
      -v "$PWD/config.yaml:/etc/hoop-inspect/config.yaml:ro" \
      hoophq/hoopsidecar:<version> hoop start sidecar --validate

    docker run -d --name hoop-atlas \
      -p 127.0.0.1:27017:27017 -p 127.0.0.1:19000:19000 \
      -v "$PWD/config.yaml:/etc/hoop-inspect/config.yaml:ro" \
      hoophq/hoopsidecar:<version>
    ```

    `--validate` prints `config OK: 1 listener(s)` and the rule counts. Versions are on the [releases page](https://github.com/hoophq/hoop/releases).
  </Step>

  <Step title="Point your clients at the Sidecar">
    Replace the `mongodb+srv://` string with a `mongodb://` string to the Sidecar. The user and password stay the same.

    ```
    before: mongodb+srv://<user>:<password>@cluster0.<id>.mongodb.net/<db>
    after:  mongodb://<user>:<password>@127.0.0.1:27017/<db>?authSource=admin&directConnection=true
    ```

    - `authSource=admin` was set for you by the `+srv` string. Atlas keeps database users in `admin`.
    - `directConnection=true` keeps the driver on the Sidecar. Without it, the driver reads the member list from the server, dials Atlas directly and fails.
    - Leave out `compressors=`. The Sidecar refuses compressed traffic.

    The new string has no `tls=true`. That applies only to the hop from the client to the Sidecar on the same host. When clients reach the Sidecar over a network, put TLS in front of it. See [TLS on each leg](/setup/configuration/hoop-sidecar/protocols/mongodb#tls-on-each-leg).
  </Step>
</Steps>

## Verify

Connect through the Sidecar:

```bash
mongosh "mongodb://<user>:<password>@127.0.0.1:27017/shop?authSource=admin&directConnection=true"
```

Insert a test document:

```js
db.customers.insertOne({ name: "Ana Souza", email: "ana.souza@example.com" })
```

A find returns the email masked:

```js
db.customers.find()
```

```
[
  {
    _id: ObjectId('...'),
    name: 'Ana Souza',
    email: '[REDACTED:column:email]'
  }
]
```

A destructive command is refused with your message:

```js
db.customers.drop()
```

```
MongoServerError: destructive commands are blocked by Hoop
```

The audit lists the session with its counts (fields trimmed):

```bash
curl -s '127.0.0.1:19000/api/sessions?denied=true'
```

```json
{"sessions":[{"principal":"anonymous","protocol":"mongodb","connection":"atlas","denied_count":1,"masked_count":1,"verdict":"denied"}],"total":1}
```

Drivers also open monitoring connections. They show in `/api/sessions` with no statements, so the example filters on `denied=true`.

## Allow only the Sidecar with the IP access list

Atlas accepts connections only from the IP addresses on the project's IP access list.

Leave only the Sidecar's egress IP on it, and no client can connect to Atlas directly and skip your rules. This needs a Sidecar host with a static egress IP, such as an Elastic IP or a NAT gateway.

1. In the Atlas UI, open **Security**, then **Database & Network Access**, then **IP Access List**.
2. Click **Add IP Address** and add the Sidecar's IP.
3. Delete every other entry, including `0.0.0.0/0`.

<Frame>
  <img src="/images/integrations/mongodb-atlas-network-access.png" alt="Atlas IP Access List with one IP address allowed" />
</Frame>

Or with the Atlas CLI:

```bash
atlas accessLists create <ip> --type ipAddress --projectId <project-id> --comment "Hoop Sidecar"
```

Editing the list needs the Project Owner or Project Network Access Manager role.

A connection from any other IP fails before it reaches the database:

```
MongoServerSelectionError: ... SSL alert number 80
. It looks like this is a MongoDB Atlas cluster. Please ensure that your Network Access List allows connections from your IP.
```

<Note>
If the Sidecar's own IP leaves the list, clients see only `connection closed`. The Sidecar log names the cause: `upstream dial failed` with `upstream TLS handshake: remote error: tls: internal error`.
</Note>

## Behavior to know

- **A denied command closes the connection.** The client reads the rule's message as error code `13`, `Unauthorized`, and an open transaction rolls back. Drivers retry reads and retryable writes on a new connection. Other commands, such as `createIndex`, can fail once with `connection closed`.
- **The audit records sessions as `anonymous`.** The Sidecar relays the login without reading the user name.
- **Database users need a password.** X.509 users cannot log in through the Sidecar, because the Sidecar opens its own TLS connection to Atlas.

## Free and Enterprise

<EnterpriseLimit />

- **More rules:** an Enterprise license lifts the one-rule caps, with or without a Control Plane. In Docker, pass it with `-e HOOP_LICENSE="$(cat license.json)"`. See [Licensing](/setup/configuration/hoop-sidecar/config-file#licensing).
- **Reviews and central management:** connect the Sidecar to a [Control Plane](/core-concepts/control-plane), which also needs an Enterprise license. It adds reviews, shared rule sets and one view of many Sidecars.
