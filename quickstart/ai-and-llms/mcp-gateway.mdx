The `mcp` connection type relays Model Context Protocol traffic as opaque HTTP. That is enough to mask data in transit, but it cannot tell the difference between a model calling `delete_issue` and the same words appearing inside a tool result.

The MCP Gateway parses every JSON-RPC message in both directions. That single change makes a class of controls expressible that a byte relay cannot offer:

- **Tool-level allow and deny lists.** Denied tools are stripped from `tools/list` before the model ever sees them, so it does not attempt a call it cannot make.
- **Approval holds on individual tool calls.** A matched `tools/call` parks for human review; the rest of the session keeps working.
- **Rug-pull detection.** Hoop fingerprints each tool's name, description and input schema. If a server silently rewrites a tool mid-session, the session is killed or flagged.
- **Sampling and elicitation gating.** A compromised server cannot drive your LLM or phish your users through elicitation dialogs; both are denied by default.
- **Budgets.** Cap calls per session, per-tool rates, and result size.
- **Structured audit.** Session review shows which tool ran, with what argument digest, how long it took and which rule blocked it, instead of request and response blobs.

Guardrails and data masking still apply, but they now run on exactly the free-text fields MCP has: tool-call arguments, tool descriptions and result text leaves. Masking cannot corrupt the JSON-RPC envelope, and guardrails stop matching against protocol framing, which removes a common source of false positives.

Both remote MCP servers and local `stdio` servers are supported. A stdio server runs as a child process under agent control with full process-group lifecycle, so an `npx`-style server is a first-class connection rather than something you have to host yourself.

### Choosing between MCP and MCP Gateway

The `MCP` connection type is a byte-level HTTP relay. It is the right choice when you only need TLS termination, session recording and data masking in front of a remote MCP endpoint.

The `MCP Gateway` connection type parses the protocol. Choose it when you need any control that names a tool: allow and deny lists, per-tool approvals, rug-pull detection, budgets, or an audit trail a reviewer can read.

Both types can run side by side against the same upstream server, so you can move one connection at a time.

### Transports

- `streamable-http` — the current remote MCP protocol. Set the server URL.
- `sse` — the legacy HTTP+SSE protocol, still used by some hosted servers.
- `stdio` — a local server the agent spawns as a child process. Supply the command and any environment the child needs.
